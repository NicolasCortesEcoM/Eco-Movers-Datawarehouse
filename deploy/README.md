# Deploying to the droplet host

**The droplet is the working environment, not your laptop.** Every structural change -
a dbt model, a seed, a file in `sql/` - is applied there in the same session it is made,
so that "going live" is a permissions change rather than a migration. Do not iterate
locally and deploy later; that divergence is exactly what left a landed report with
nothing reading it in August 2026.

Everything runs on the droplet **host** (same box as n8n + Postgres). n8n runs in Docker
without python, so it orchestrates via **SSH Execute** nodes that call into the host.

## The one command you need

```bash
python deploy/sync_droplet.py            # sync + dbt seed + build + test
python deploy/sync_droplet.py --sql      # also replay sql/*.sql (idempotent DDL)
python deploy/sync_droplet.py --no-build  # sync files only
python deploy/sync_droplet.py --select 'stg_smartmoving__report_lead_status+'
```

It packs `dbt/`, `pipeline/`, `scripts/` and `sql/`, uploads them over SSH, writes the
host `.env` (chmod 600) from your laptop `.env`, creates the venv on first run, and
builds under `flock` so a manual run can never collide with a scheduled one.

Credentials come from the repo `.env` (`droplet_ssh_host`, `droplet_ssh_user`,
`droplet_ssh_password`, `droplet_platform_rw_*`). Nothing is hardcoded here.

## Layout on the host

```
/home/datawarehouse_user/datawarehouse/
  .env          # generated by sync_droplet.py, chmod 600 - do not edit by hand
  dbt/          # models, macros, seeds, profiles.yml
  pipeline/     # run.py + sm_pipeline/
  scripts/      # api_call_log.jsonl lives here
  sql/          # bootstrap + RLS + landing-table DDL
  venv/         # dbt-postgres, dlt, requests
```

> **Why not `/opt/datawarehouse`, as earlier drafts of this file said?** `/opt` on this
> droplet is mode 700 owned by another application's service user. Creating a
> subdirectory there would mean loosening permissions on a directory that is not ours.
> The service account's home directory needs no sudo and interferes with nothing.

## What is excluded from the sync, and why

`target/`, `logs/`, `dbt_packages/`, `__pycache__`, `.user.yml`, `*.duckdb`,
`api_call_log.jsonl`. Build artifacts are machine-specific: shipping a stale `target/`
makes dbt's state comparisons lie, and overwriting the host's call log would destroy the
record of API quota already spent.

`sql/00_bootstrap.sql` is also skipped on `--sql`. It creates schemas, roles and the RLS
control table, which needs a superuser; it ran once at provisioning. `platform_rw` cannot
run it, so including it would fail every deploy.

## One-time setup (already done - kept for rebuilding from scratch)

1. Superuser runs `sql/00_bootstrap.sql` (schemas, `platform_rw`, `app_read`,
   `core.entity_access`, default privileges).
2. `python deploy/sync_droplet.py --sql` - creates the venv and builds everything.
3. **n8n SSH credential** (n8n UI -> Credentials -> SSH): host `<n8n_docker_gateway>`
   (the Docker->host gateway, from laptop `.env`), port `22`, user `<droplet_ssh_user>`.
   The schedule and worker workflows reference it.

`host_bootstrap.sh` predates `sync_droplet.py` and only covers the pipeline. It is kept
for reference; prefer the sync script.

## How n8n invokes the host

Extraction:
```
cd /home/datawarehouse_user/datawarehouse/pipeline && ../venv/bin/python run.py \
  --ids <ids> --instance <inst> --dest postgres --budget 200 --pace 0.6
```

Transformation (see `n8n_dbt_build_reports.json`):
```
out=$(flock -w 900 /tmp/dw-dbt.lock -c '...dbt seed && dbt build...' 2>&1); rc=$?; \
echo "$out" | tail -60; exit $rc
```

⚠️ **Never write this as `dbt … | tail -60`.** A pipeline returns its LAST stage's exit
code, so `tail` would report success no matter how badly dbt failed, and the schedule
would stay green over a warehouse that stopped building. Capture, print, re-raise.

⚠️ **Every dbt invocation must be wrapped in `flock`.** The enrichment worker triggers
builds too; two overlapping runs drop and recreate the same tables, and the loser writes
into objects the winner already replaced.
